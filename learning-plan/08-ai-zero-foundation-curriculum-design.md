# AI 零基础开发者课程改造设计

日期：2026-08-26

## 改造目标

将课程学习对象从“具有后端开发经验、希望进入 AI 工程的程序员”调整为“具备基础开发能力、但没有 AI、机器学习、LLM、RAG 和 Agent 知识的开发人员”。

课程仍保持 32 周、每天约 1 小时，最终目标、必修知识、平台范围、业务落地闭环和成果门禁不变。改造只调整教学起点、概念顺序、前置诊断、练习脚手架和复习机制，不通过删除框架、安全、评测、失败场景或业务流程内容降低难度。

## 学习者画像

默认学习者已经具备：

- 能使用至少一种主流编程语言完成小型功能和单元测试。
- 能使用 Git、命令行和 IDE，能阅读错误日志并进行基础排错。
- 理解 HTTP、JSON、数据库和常见 Web API 的基本概念。
- 能按照 README 在本地运行项目。

课程不默认学习者具备：

- AI、机器学习、深度学习、概率统计或线性代数知识。
- LLM、Token、Embedding、Prompt、RAG、Tool Calling 或 Agent 心智模型。
- Spring AI、LangChain、LangGraph、Claude Agent SDK 或 MCP 使用经验。
- Java 21、Spring Boot 或 Python 异步编程的完整熟练度。
- AI Eval、Prompt Injection、模型成本和业务 AI 流程设计经验。

Java、Spring Boot 和 Python 只补充完成课程所需的工程桥接内容。若学习者连通用开发、HTTP、Git 或测试基础也不足，需要在课程外补充，不降低 AI 课程出口标准。

## 不变约束

以下内容不得因零基础改造而改变：

1. 周期仍为 32 周，日均投入约 1 小时。
2. 最终交付仍为 `AI Agent Platform + Business Case`。
3. Spring AI、LangChain、LangGraph 和 Claude Agent SDK 均为必修。
4. 原生模型 API、流式事件、结构化输出和手写 Tool Loop 必须先于高层 Agent 框架。
5. RAG、Tool/MCP、工作流、Checkpoint、审批、权限、Eval、可观测性、安全和运维能力不得删除。
6. 业务落地仍覆盖场景发现、AS-IS、TO-BE、系统接入、UAT、试点、灰度、回退和效果复盘。
7. 每周仍需运行证据、失败或边界案例、Teach-back 和变体任务。
8. 阶段出口和最终交付标准不降低；补救任务可以调整进度，但不能虚假标记通过。

## 教学模型

### 每日零基础学习闭环

每天只引入一个核心新概念，并按以下顺序完成：

```text
已有开发经验类比
→ 一句话定义和最小术语集
→ 可观察的最小实验
→ 一个反例、失败或安全边界
→ 学习者 Teach-back
→ 一个改变输入或约束的小型变体
```

讲师第一次使用专业术语时必须给出通俗定义、工程类比和“不是什么”。学习者能够运行示例但不能解释输入、输出和失败原因时，只判定为 L1，不判定掌握。

### 三次接触原则

核心概念至少经历三次不同层次的接触：

1. 首次建立直觉并观察现象。
2. 在代码或实验中实现并制造失败。
3. 在后续框架或平台能力中迁移、比较和治理。

例如 Tool Calling 在原生 API 中观察协议，在 Spring AI/LangChain 中学习抽象，在平台 Tool Registry、权限和审计中完成生产治理。

### 新阶段桥接

每个阶段开始前增加：

- “开始前应会什么”：只列真实依赖。
- “零基础桥接”：用 15–30 分钟最小任务补齐语言、框架或业务方法。
- “本阶段不要求什么”：防止过早学习数学推导、历史 API 或大型基础设施。
- “前测失败处理”：先执行补救任务，不直接堆叠新内容。

## 32 周节奏

周次和知识范围保持不变，教学重点调整如下：

| 周次 | 零基础教学调整 | 原有核心成果 |
| --- | --- | --- |
| 1 | 先区分 AI/ML/深度学习/生成式 AI/LLM，再学习推理、Token、Embedding、采样和幻觉 | LLM 工程实验与心智模型 |
| 2 | 从 HTTP 请求响应和逐 Token 生成映射到模型 API、SSE、结构化输出和 Tool 协议 | 原生模型客户端和 Tool Loop |
| 3 | 从普通函数契约映射到 Prompt 契约，引入固定样例和最小 Eval 思维 | Prompt 版本与 AI 编程协作 |
| 4 | 把 AI 调用拆成确定性代码与不确定模型，建立 Fake、错误分类、Trace 和架构表达 | 原生 AI 服务工程基线 |
| 5–8 | 先映射原生实现与 Spring AI 抽象，再学习 Chat、RAG、Tool 和 Java Agent | Java AI 应用能力 |
| 9–11 | 提供 Python/Pydantic/async 最小桥接，再学习 LangChain 与 LangGraph | Python Agent 和可恢复工作流 |
| 12–13 | 从“模型调用”过渡到“开放式执行 Harness”，逐步开放 Read、Edit、Bash、MCP | 安全执行型 Agent |
| 14–16 | 用单请求、单 Trace、固定数据集先形成组合与 Eval 直觉 | 可评测端到端应用 |
| 17–24 | 每项平台能力先从单应用痛点出发，再抽象控制面、执行面与治理 | AI 平台 MVP |
| 25–28 | 先补业务术语和流程图方法，再进行场景、AS-IS、TO-BE 和接入设计 | 业务方案包 |
| 29–32 | 通过 Stub、UAT、试点、故障演练和复盘把设计转成可验证交付 | 平台发布与业务案例 |

## 成果与掌握度调整

最终成果门禁不变，前期增加以下学习证据：

- 第 1–4 周维护必要术语和心智模型，但禁止复制百科式定义。
- 每个实验写明“输入、观察、解释、反例、工程意义”。
- 每个新框架必须说明它替代了哪段原生实现、增加了哪些状态和失败模式。
- 每周至少一个问题要求学习者从未见过的输入或限制迁移，而不是重复教程。
- 讲师反馈记录使用的最高提示级别；依赖 H4 完整答案完成后必须追加变体。

阶段出口仍使用现有评分，但讲师需要区分：

- “第一次接触尚未记住”：通过术语卡和间隔复习解决。
- “错误心智模型”：通过反例和最小实验纠正。
- “工程实现阻塞”：通过 H1–H4 提示阶梯解决。
- “缺少运行证据”：不得用讲解或文档代替。

## 验收标准

课程改造完成后必须满足：

1. 所有入口文档均明确“开发基础、AI 零基础”的学习对象。
2. 32 周、每天约 1 小时、最终目标和技术路线保持不变。
3. 第 1 周不以未解释的 Transformer/Attention 术语作为起点。
4. 九个阶段均给出前置能力、零基础桥接和不要求内容。
5. 每日计划仍保持四列表格，并包含学习建议和验收。
6. Spring AI、LangChain、LangGraph、Claude Agent SDK 各自保留独立成果和平台集成成果。
7. 原生 API、失败测试、安全、Eval、平台治理和业务流程内容没有减少。
8. 32 个周成果索引、阶段周次和进度扫描保持一致。
9. 文档链接、格式检查和进度扫描通过。
