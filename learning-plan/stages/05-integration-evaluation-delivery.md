# 阶段五：组合、评测与首个 AI 应用

周期：第 14–16 周，共约 21 小时。

目标：将 Java RAG 服务、LangChain/LangGraph 工作流和 Claude Agent 执行层组合成可测量、可审计、可复现的首个 AI 应用，为后续平台化提取稳定能力和运行基线。

## 开始前应会什么

- 能分别运行 Java API、Python Agent、LangGraph 工作流和隔离的 Claude Agent 练习。
- 能说明 Schema、traceId、超时、取消、审批和错误状态的基本作用。
- 能使用固定输入重复运行实验，不用单次成功代替质量结论。

## 零基础桥接

先画一张单请求时序图，只包含业务调用者、Java API、Python/LangGraph、Claude Agent、模型和 Tool，并标出每层输入输出与失败。Eval 先掌握“固定输入、预期结果、评分规则、Baseline”四个词，再增加数据集、Runner、Trace、成本和版本对比。

## 本阶段不要求什么

- 不要求先引入消息队列、微服务拆分、复杂前端或商业评测平台。
- 不要求一次组合所有框架能力；先打通一个只读请求，再增加审批和失败路径。
- 不要求追求高分或漂亮演示，失败样例和未验证范围必须保留。

## 前测失败处理

若无法画清单请求职责，先用 Stub 替代模型和 Agent，只验证版本化 Schema、traceId 与错误映射；若不会定义 Eval，则先为 3 条固定输入手写预期和通过/失败规则，再扩大数据集。

## 第 15 周：Eval 与可观测性

| 日期 | 学习任务 | 当天学习建议 | 当天验收 |
| --- | --- | --- | --- |
| 周一 | 定义 RAG 和 Agent 指标 | 每个指标写清计算公式、数据来源和好坏方向，避免“整体感觉不错” | 指标有明确判断方法 |
| 周二 | 准备 20 条 RAG 问题 | 在看系统结果前先写预期答案与来源；加入无答案和相似干扰问题 | 覆盖事实、路径、总结和拒答 |
| 周三 | 准备 10 条 Agent 任务 | 每个任务提供初始工作区、允许副作用和机器可执行的验收命令 | 覆盖只读、修改、失败和拒绝 |
| 周四 | 统一 Trace、日志和成本字段 | 使用同一任务 ID 贯穿服务；日志字段稳定，敏感内容脱敏且大输出截断 | Java/Python 关联同一任务 |
| 周五 | 跑第一轮 Baseline | 冻结模型、Prompt、数据和参数；保存全部原始结果，包括超时和失败 | 保存完整原始结果 |
| 周六 | 只调整一个主要变量并复测 | 选择最可能影响失败的变量，记录假设；不要为了提升分数删除困难用例 | 有可解释对照 |
| 周日 | 分析失败并形成报告 | 按检索、生成、工具、流程、环境分类失败，并给出下一步验证而非空泛结论 | 完成本周提交 |

建议指标：

- RAG：答案正确率、检索命中率、引用命中率、拒答准确率。
- Agent：任务完成率、测试通过率、审批命中率、越权阻断率。
- 工程：P50/P95 延迟、Token、成本、平均步骤和工具失败率。

## 阶段出口条件

- Java API 与 Python Worker 能端到端通信。
- LangGraph 明确控制哪些任务只读、需审批或拒绝。
- Claude Agent 只在隔离工作区执行。
- RAG 和 Agent 都有固定评测集、Baseline 和失败分析。
- 运行、测试、评测和演示均有文档。
- 能在 10 分钟内解释业务价值、架构取舍、效果和风险。

## 学习建议

- 组合阶段优先打通一个最小请求，不要先引入消息队列和复杂分布式架构。
- API 协议使用版本化的结构化对象，不直接传递不可控的大段 Agent 文本。
- 跨服务必须传播 `traceId`，否则失败时难以定位在哪一层出错。
- Eval Runner 与业务代码分离，避免为了让评测通过而写特殊分支。
- 最终演示要包含失败与阻断场景，它们比只展示成功回答更能说明工程能力。
- 面试表达按照“问题 → 方案 → 证据 → 失败 → 优化 → 风险”组织。
