# 阶段十一：Super-agent 持续执行、恢复与独立交付

周期：第 37–40 周，共约 28 小时，另需一次连续 24 小时后台观察。

目标：让已具备事件接入与三任务协作能力的系统，在中途纠正、取消、撤权、进程退出和长期运行时仍可控；用公平对照和陌生变体验证独立设计与交付能力。项目与指标口径以[强化课程设计](../11-super-agent-reinforcement.md)为准；逐节入口见[教程索引](../tutorials/README.md)。

## 本阶段语言定位

Java 控制面继续持有任务、命令、授权与副作用凭证；Python Worker 执行不可变发布快照并报告进展。复用现有数据库、LangGraph 持久化与 Claude 沙箱，不另建一套权限或状态真相。测试先用持久 Fake/Stub 和可控时钟，真实模型质量与实际墙钟运行分别记录。

## 开始前应会什么

- 原课程毕业与阶段十出口均已通过，三任务与两入口演练可复现。
- 能解释来源身份、Project、Task、Run、revision 与租约，并拒绝一次跨任务/跨租户关联。
- 能运行开发集，说明队列容量、授权规则、通知规则与单会话基线。

阶段前测：让一个慢工具占用 Worker，同时从第二入口提交同一任务的补充信息；学习者先预测控制面能否接收、何时生效，再运行观察。无法独立定位阻塞或身份关联问题时先补阶段十。

## 零基础桥接

按缺口选择 15–30 分钟练习：用异步 Fake 观察事件循环、用版本条件更新阻止旧结果覆盖、或读取原平台的持久 Checkpoint 并重启恢复。只补当天依赖，保存预测、命令、结果与一个反例。

## 本阶段不要求什么

不要求无人值守生产运行、不受限自我改进、跨地域高可用或对任意外部系统保证 exactly-once。无法查询或幂等的外部写入必须进入未知状态并交人工核对，不能用重试掩盖不确定性。

## 前测失败处理

先形成补救任务和复测证据，不提前执行依赖未通过能力的长时间实验。记录对后续日期的影响；不得压缩撤权、崩溃和独立考试来追赶周次。

| 周日 | 独立纠正变体验收 | 关闭本周代码说明，把取消改成缩小任务范围；解释接收、生效、撤权与补偿各自边界，独立完成一个最小变体<br>相关资料：[讲师规范](../07-instructor-supervision.md) | Teach-back、变体运行、周评和待补救项 |

本周提交：命令 Schema、状态迁移、修订/取消/撤权测试和跨入口时间线，在个人仓库 `deliverables/week-37/README.md` 链接。最低验收：控制输入不被长工具阻塞，权限变化生效，终态和已发生副作用不被描述性文字掩盖。

## 第 38 周：多任务持久恢复与副作用核对

| 日期 | 学习任务 | 当天学习建议 | 当天验收 |
| --- | --- | --- | --- |
| 周一 | 持久恢复边界 | 恢复边界保存足够重建执行的数据，输入为已接受事件与执行进展，输出为重启后可核对状态，类比事务日志。内存快照不能证明进程退出恢复；复用第 22 周持久化<br>相关资料：[LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence) | 明确 Task/Run/命令与 Checkpoint 的归属，关闭进程后状态可恢复 |
| 周二 | 事务 Outbox | Outbox 把状态变更和待派发意图同事务保存，输入为接纳结果，输出为可重试投递记录，类比登记后待寄的凭条。它可能重复投递，不承诺外部 exactly-once<br>相关资料：[DeepSeek Architecture](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/007-architecture.md) | 提交后派发前退出不会丢任务；重复派发由接收方幂等拒重 |
| 周三 | 拦截过期 Worker | fencing 是以单调 epoch 拦截失效持有者，输入为 Worker 的租约版本，输出为接受或拒绝，类比换锁后旧钥匙失效。租约过期不会杀死旧进程；写入口必须校验 epoch<br>相关资料：[DeepSeek Execution](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/003-execution.md) | 旧 Worker 延迟返回或尝试写入被阻断，新 Worker 可接管；无法校验的外部端列明限制 |
| 周四 | 未知副作用核对 | 未知状态表示无法确认外部动作是否成功，输入为幂等键与查询凭证，输出为已完成/未发生/需人工，类比银行交易对账。超时不等于失败；先查再决定补做<br>相关资料：[原课程持久运行时](07-workflow-governance.md) | 外部写成功后断回执再重启，计数仍为 1；无法查询时停止重试并交人工 |
| 周五 | 三任务重启重建 | 组合事件、命令、租约和副作用凭证，分别恢复排队、执行中、等待审批的三个任务；恢复仍使用原授权版本并校验当前权限<br>相关资料：[LangGraph Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts) | 三任务状态可解释，审批未自动放行，完成动作未重复，权限撤销仍阻断 |
| 周六 | 退出级故障注入 | 在事件入库后、派发后、外部成功未本地确认三处终止实际进程；用持久外部 Stub 保留写入结果，测试重启不能清空账本<br>相关资料：[专项恢复门禁](../11-super-agent-reinforcement.md#固定评测集与专项门禁) | 三处退出命令、恢复 Trace、事件计数与外部动作计数；区别于函数抛异常测试 |
| 周日 | 陌生故障位置复验 | 讲师将退出位置改到命令已接收但未生效；学习者先判断证据来源，再独立修复或解释安全停机，不能手工改库制造成功<br>相关资料：[阶段考试](../07-instructor-supervision.md#阶段考试) | 新故障定位、可重放记录、周评和恢复限制 |

本周提交：恢复边界图、持久存储约束、Outbox/epoch/幂等实现与退出级实验。最低验收：没有静默丢失或重复已完成副作用；未知结果显式阻塞，恢复不扩大权限。

## 阶段出口

- 第 37–40 周核心成果通过，原主线毕业与阶段十通过记录可追溯。
- 三任务与两入口保持可用；中途纠正、取消、拒绝、超时和撤权有独立轨迹。
- 三处真实进程退出恢复和持续观察达到[统一专项门禁](../11-super-agent-reinforcement.md#固定评测集与专项门禁)，未知副作用按安全路径停止。
- 30 条固定场景完成三轮公平对照；开发集、留出集、Fake 与真实模型结果分开报告。
- 能在有限提示下独立设计、实现、排错并迁移一个陌生约束变体，不把看过答案的练习计为独立考试。
- 能说明系统边界、成本与人工责任，作出有证据的推广/调整/停止决策。专项通过不等于达到上游内部系统规模或生产成熟度。
