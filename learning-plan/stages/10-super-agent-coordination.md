# 阶段十：Super-agent 任务协作与事件接入

周期：第 33–36 周，共约 28 小时，接在原 32 周毕业之后。

目标：复用已验收的平台，独立设计并实现三任务并行、事件接入和两渠道任务关联。项目边界、固定案例集和来源差异以[强化课程设计](../11-super-agent-reinforcement.md)为准；逐节入口见[教程索引](../tutorials/README.md)。

## 本阶段语言定位

Java 控制面管理 Task/Run、调度状态、身份和权限；Python Worker 执行已有 Agent，保留四个框架的职责边界。持久存储复用 PostgreSQL，先用本地适配器和 Fake Worker 验证控制逻辑，再连接受控执行器。不要为了参照上游原型重写为 TypeScript 或引入新框架。

## 开始前应会什么

- 原九个阶段出口、第 32 周平台与业务双验收均已通过。
- 能现场运行一个不可变发布版本，说明任务、运行、权限、Trace 与副作用凭证的关系。
- 能复现第 22 周进程退出恢复，说明“请求已发送”和“业务写入已成功”的差别。

阶段前测：只给一条重复请求、一次工具超时和一个无权用户，学习者使用原平台判断状态、运行验证并解释为何不能盲重试。未通过时不得用新架构掩盖旧问题。

## 零基础桥接

按前测薄弱项选择一个 15–30 分钟小任务：用数据库唯一约束阻止重复记录；用两个异步 Fake 任务观察阻塞；用现有测试验证 Project 隔离。桥接完成要提交命令和一个失败结果，当天核心任务可缩小，验收顺序不变。

## 本阶段不要求什么

不要求运行 DeepSeek 原型、申请真实聊天账号、多仓库调度、微服务或复杂多 Agent 拓扑。两个本地协议适配器足以验证行为，真实平台接入范围须如实标注。

## 前测失败处理

先记录缺口、补救任务、复测证据和后续日期影响；原平台不能稳定执行/拒绝/恢复时，暂停依赖它的专项实现。连续两次未通过按讲师规范缩小实验，不降低权限和恢复门禁。

## 第 33 周：独立设计与单会话基线

本周只确定一个受限项目及其最小可运行切片。周一、周六、周日用于复习和验证，不增加新框架。

| 日期 | 学习任务 | 当天学习建议 | 当天验收 |
| --- | --- | --- | --- |
| 周一 | 前测与任务需求契约 | 完成阶段前测；用现有 Scene Brief 方法写角色、三类研发任务、允许副作用、成功条件和人工接管点。需求契约把模糊目标变成可验证输入输出，类比接口验收；“自动解决所有问题”不是契约<br>相关资料：[专项项目边界](../11-super-agent-reinforcement.md#贯穿项目与技术职责) | 前测结果、一个可验收需求和一个明确拒绝的越界需求 |
| 周二 | 区分 Task 与 Run | Task 表示持续目标，Run 表示一次执行尝试；输入是目标和执行请求，输出为稳定 taskId 与不同 runId，类比订单与处理尝试。重试不能新建同一个业务目标<br>相关资料：[DeepSeek Domain model](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/001-domain.md) | 两次尝试归属同一 Task 的 Schema、状态例子与重复创建反例 |
| 周三 | 路由建议与确定性接纳 | Router 给出去向建议，平台用普通代码决定是否接纳；输入为事件摘要，输出为新建、关联、忽略或待人工。类比建议单与审批系统；模型说“允许”不产生权限<br>相关资料：[DeepSeek Architecture](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/007-architecture.md) | 一张边界图、两种方案取舍，以及非法路由建议被拒绝的测试 |
| 周四 | 固定任务执行契约 | 复用第 14/18 周协议，增加 taskId、runId、revision、release、project、deadline 与授权引用；输入为已接纳任务，输出为 Worker 接受或拒绝，类比带版本的工单。缺字段不得自行补权限<br>相关资料：[平台架构规则](../../AGENTS.md#平台架构规则) | 契约样例和过期版本、缺失身份两条失败测试 |
| 周五 | 冻结对照场景 | 按专项要求建立 30 条案例清单，讲师保管 10 条留出输入；固定数据、模型条件、顺序和评分，类比稳定回归夹具。只挑成功样例不是基线<br>相关资料：[固定评测集](../11-super-agent-reinforcement.md#固定评测集与专项门禁) | 20 条开发输入、10 条留出索引、评分规则及环境阈值；未运行结果留空 |
| 周六 | 运行单会话基线 | 复用已发布单 Agent 完成开发集中三个代表任务，记录完成状态、总成本、耗时与人工操作；失败也计入，模型不可用则明确 Fake 范围<br>相关资料：[成果标准](../06-deliverable-standards.md) | 可重跑命令、原始脱敏记录和一个失败定位，不声称全量质量已验证 |
| 周日 | 独立解释设计取舍 | 关闭本周图和教程，解释为何拆或不拆 Router/Worker；把一个目标改成纯确定性任务，说明何时普通函数足够<br>相关资料：[阶段考试](../07-instructor-supervision.md#阶段考试) | 周评、Teach-back、独立变体与学习债务 |

本周提交：个人仓库中的需求与 ADR、协议、基线版本、固定案例清单、单会话运行记录；在 `deliverables/week-33/README.md` 链接。最低验收：能从新需求说明边界，非法建议不能越过平台校验。

## 第 34 周：并发调度与任务隔离

| 日期 | 学习任务 | 当天学习建议 | 当天验收 |
| --- | --- | --- | --- |
| 周一 | 有界工作队列 | 队列把待执行任务与 Worker 容量解耦，输入为已授权 Task，输出为排队或派发，类比线程池。无限列表不是容量策略；先用三个 Fake Worker 和可控时钟<br>相关资料：[DeepSeek Execution：Concurrency](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/003-execution.md#concurrency) | 三任务可并行，第四个按容量排队，队列满时状态明确 |
| 周二 | 公平调度 | 公平性避免某个来源长期占有槽位，输入为优先级与等待时间，输出为确定的选择顺序，类比排班。一直选新高优先任务会饿死旧任务<br>相关资料：[DeepSeek Execution](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/003-execution.md) | 高频来源与低频来源同时到达时，无无限等待；公开选取规则 |
| 周三 | 租约与唯一执行权 | 租约是有期限的执行占有，输入为任务与 Worker，输出为 owner、epoch 和 expiresAt，类比有到期时间的借用单。租约过期不代表旧进程已停；先验证正常抢占<br>相关资料：[DeepSeek Architecture](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/007-architecture.md) | 两个 Worker 竞争只获一个有效租约，过期路径明确；旧 Worker 拦截留待第 38 周深化 |
| 周四 | 隔离工作目录 | 复用沙箱，为每个 Task 绑定工作目录和允许工具；输入为任务授权，输出为受限执行环境，类比每个构建的独立工作区。同目录不同会话不是文件隔离<br>相关资料：[Agent 与安全规则](../../AGENTS.md#数据密钥与安全) | 三任务互不覆盖文件，跨目录访问被阻断，测试不接触主工作仓库 |
| 周五 | 任务预算预留 | 预算预留是在派发前占住有限额度，输入为任务上限，输出为允许、等待或拒绝，类比库存预占。只在结束时计费不能阻止并发超支<br>相关资料：[固定评测集与门禁](../11-super-agent-reinforcement.md#固定评测集与专项门禁) | 并发下全局与单任务预算均受控，失败/取消后释放规则可验证 |
| 周六 | 三任务竞争演练 | 用三个开发案例组合调度、目录隔离和预算；一个慢任务持续运行时另外两个仍推进，记录队列与执行时间线<br>相关资料：[专项验收](../11-super-agent-reinforcement.md#固定评测集与专项门禁) | 三任务 Trace、容量断言、一次资源耗尽故障及排错结论 |
| 周日 | 调度变体验收 | 不看实现，将容量从三降到二，再改变任务到达顺序；先预测状态后运行，复述租约为何不能独自保证副作用不重复<br>相关资料：[讲师规范](../07-instructor-supervision.md) | 独立预测与运行一致、周评和下周稳定输入 |

本周提交：调度规则、租约 Schema、沙箱配置、预算断言和三任务时间线。最低验收：并行可观察，资源有上限，隔离不靠 Prompt；仍未验证的崩溃接管明确列入第 38 周输入。

## 第 35 周：事件驱动与主动触发

| 日期 | 学习任务 | 当天学习建议 | 当天验收 |
| --- | --- | --- | --- |
| 周一 | 统一事件信封 | 事件信封包装发生过的事实，输入为来源消息，输出为 source、eventId、actor、project、occurredAt 与 payloadRef，类比消息总线信封。正文不是可信 actor；先接本地 Issue 适配器<br>相关资料：[DeepSeek Domain model](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/001-domain.md) | 合法事件可解析，缺来源/伪造主体被拒绝；保留版本与数据来源 |
| 周二 | 持久接收与去重 | Inbox 是已接收事件的持久清单，用 source+eventId 唯一键保证重复投递只接纳一次，类比收件签收簿。时间戳相同不代表同一事件<br>相关资料：[DeepSeek Architecture：Intake](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/007-architecture.md) | 重复投递、乱序和重启后重投不重复开工；乱序不倒退终态 |
| 周三 | 主动触发规则 | 主动触发把已授权规则与事件匹配，输入为事件和规则版本，输出为忽略、仅观察或可建任务，类比受控定时作业。模型感兴趣不等于用户授权；先只观察<br>相关资料：[DeepSeek Authorization](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/002-authorization.md) | 明确请求、规则命中、普通聊天三类结果；观察模式不产生副作用 |
| 周四 | 任务订阅 | 订阅把特定事件送给已有任务，输入为 Task 与过滤条件，输出为受限上下文，类比订阅工单更新。收到消息不授予新权限；任务结束后清理订阅<br>相关资料：[DeepSeek Authorization：Subscriptions](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/002-authorization.md#subscriptions-continuing-existing-work) | 相关事件只送目标任务，过期订阅不唤醒终态任务；越界请求交人工 |
| 周五 | 背压与重放边界 | 背压在生产速度高于处理速度时限制接入，输入为事件负载，输出为限流、排队或显式失败，类比有容量的缓冲区。静默丢弃不是背压<br>相关资料：[专项门禁](../11-super-agent-reinforcement.md#固定评测集与专项门禁) | 突发事件不突破上限，拒绝/延迟可查询，来源重投仍满足去重 |
| 周六 | 通知策略与防自激 | 复用去重和触发规则，只为可用结果、待决策或阻塞通知；机器人自己的回执不得再次触发工作，类比告警抑制。持续发送“还在运行”不是有效进展<br>相关资料：[DeepSeek Philosophy](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/000-philosophy.md) | 完成、需审批、噪声各有通知断言；回执回流不造成事件循环 |
| 周日 | 事件变体验收 | 更换事件到达顺序、重复次数或规则版本，先预测应新建、关联、忽略还是待人工；复述授权与上下文的差别<br>相关资料：[讲师规范](../07-instructor-supervision.md) | 可重放事件集、周评、失败解释与独立变体 |

本周提交：事件 Schema、接收表、触发规则版本、订阅与通知测试。最低验收：重复不重复开工，无规则不主动执行，噪声和机器回执不会自激。

## 第 36 周：跨渠道身份与任务上下文

| 日期 | 学习任务 | 当天学习建议 | 当天验收 |
| --- | --- | --- | --- |
| 周一 | 可信身份映射 | 身份映射将渠道账号绑定平台主体，输入为接入层验证的 sourceUserId，输出为 principalId 与 Project，类比第三方账号绑定。同昵称不等于同一人；新增本地聊天适配器<br>相关资料：[DeepSeek Authorization](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/002-authorization.md) | 两入口同主体可识别，同名异人和缺失绑定默认拒绝 |

## 阶段出口

- 第 33–36 周核心成果全部通过，能独立解释模型建议与平台决定的边界。
- 三任务同时推进且彼此隔离，两入口授权补充可关联同一 Task。
- 重复、乱序、无规则事件、机器人自激和跨 Project 注入均有实际阻断证据。
- 需求修订与发布快照分离；记忆有归属与清理机制。
- 完成一次只给需求的独立设计、故障诊断和迁移；复制教程不能代替考试。
- 运行中纠正、多任务崩溃接管和持续运行留到阶段十一验收，本阶段不得提前标为通过。
