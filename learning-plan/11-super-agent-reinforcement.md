# Super-agent 强化课程与项目边界

本专项在原 32 周主线之后追加第 33–40 周，约 56 小时、56 节课；合计 40 周、约 280 小时。第 1–32 周的 AI 原理、四个框架、平台 MVP、业务案例及全部门禁保持不变。第 32 周验收原课程毕业，第 40 周单独验收 Super-agent 专项；任一项不能替代另一项。

这里的 Super-agent 指能够在明确授权范围内持续接收事件、协调多个任务、接收中途纠正并从故障中恢复的 Agent 系统。它包含模型、普通程序、持久状态和人工责任，不是一个更大的模型，也不是无限权限或无限循环的 Agent。

## 追加原因与进入条件

原课程已经训练单任务执行、状态工作流、权限、恢复和业务交付；本专项补齐跨任务调度、跨渠道关联、持续事件输入和长期运行的综合验证。它属于用户选择的强化路线，不反向提高原课程的毕业门槛。

- 进入前必须通过原九个阶段出口和第 32 周平台、业务双验收；四个框架的独立成果仍需保留。
- 能独立解释第 22 周的回执丢失与幂等恢复、第 23 周的审批与授权、第 24 周的发布门禁，并运行原有测试。
- 完成阶段十前测；薄弱项先做 15–30 分钟桥接，核心依赖不通过时补救后再进入。
- 56 小时是复用既有平台的主动学习预算，不是从空仓库开发完整产品的工期承诺。环境桥接、外部联调、补救和 24 小时后台观察会增加日历时间。

## 贯穿项目与技术职责

项目是“面向一个隔离练习仓库的持续研发协作 Agent”。默认只覆盖三类任务：分析缺陷、形成小范围代码修复、检查测试结果。结果交付为隔离目录中的 Diff、测试报告和待人工审查的建议。

两个入口可以是本地 Issue 事件适配器和聊天适配器，均使用合成身份、持久 Stub 和脱敏样例。接入真实 GitHub/飞书是后续替换适配器的迁移，不是必须申请账号才能学习的前置条件；真实发消息、提交、合并或部署必须另有具体授权。本课程追加不会安装或直接运行上游原型。

| 模块 | 职责与边界 |
| --- | --- |
| Java 控制面 | Task/Run 真相、身份绑定、授权与审批、配额、版本、调度状态和审计；状态更新由普通代码与数据库约束执行 |
| 路由判断 | 模型可建议新建、关联、忽略或交人工；控制面校验 Schema、资源归属、授权和版本后才接纳建议 |
| Python Worker | 运行已授权的不可变快照；LangChain 复用工具抽象，LangGraph 复用状态/Checkpoint，Claude Agent SDK 在沙箱内执行文件与测试任务 |
| 接入适配器 | 把来源事件归一化、保留来源 ID 与投递位置；身份由可信接入层提供，消息正文不得自报权限 |
| 持久存储 | 复用现有 PostgreSQL；保存事件、命令、Run、租约和副作用凭证；大输出只保存受权限保护的引用 |
| 控制台 | 复用任务、运行、审批和故障入口，只反映服务端状态；不新建拖拽编排器 |

Router（路由器）负责决定任务去向，Worker（执行者）负责已接纳任务中的工作；可类比调度台和施工小组。调度台不能仅凭聊天内容扩大施工许可，执行者也不能改变平台授权。初版仍是模块化单体加受控 Worker，不要求微服务、Kafka、Kubernetes 或新的 Agent 框架。

## 固定评测集与专项门禁

以下是课程设计的验收要求，不是 DeepSeek 官方指标。第 33 周建立至少 30 条带 Case ID 的固定场景：正常任务、重复/乱序事件、身份与关联、调度与隔离、中途修订、取消竞态、审批/撤权、崩溃恢复、资源耗尽、注入/噪声各 3 条。每类 2 条开发、1 条留出，即 20 条开发集与 10 条留出集；留出输入和故障位置由讲师保管，学习者可提前看到验收维度，不可逐题调参。

每条记录输入事件及顺序、主体与权限、版本、预期状态、允许副作用次数、是否应通知、截止时间与评分规则。可以组合多种边界，但不能删除难例来提分。第 33–39 周只使用开发集；第 40 周冻结发布版本后一次性评审留出集。留出失败先记录原因，修复后用新留出变体复验，保留旧结果。

| 验收项 | 最低证据 |
| --- | --- |
| 多任务 | 三个任务同时处于活动态，一个长工具任务不阻塞另两个任务与控制命令；单任务活动 Worker 不重复占有；资源上限与公平性可断言 |
| 两入口 | 两入口的授权用户补充可关联同一 Task；同名不同主体、不同 Project 和歧义事件均不能自动串任务；关联错误可撤销且留审计 |
| 事件与通知 | 同一事件重复投递不重复建任务或写入；忽略、拒绝、待人工和失败均可查询；任务完成、需决策、阻塞各通知一次，普通轮询不反复打扰 |
| 纠正与终止 | 长工具运行中仍能持久接收修订和取消；明确“已接收”与“已生效”；生效前已发生的副作用有凭证，终态后迟到结果不能重新启动工作 |
| 安全 | 审批拒绝、超时、撤权、越权、注入全部按预期阻断；恢复与子任务不得扩大原授权；授权撤销后不再发起新副作用，已在途操作进入核对 |
| 恢复 | 至少三处进程退出注入：事件入库后、派发后、外部写成功但本地未确认时；重启恢复三个任务，无事件静默丢失；已完成副作用计数为 1，无法核对则停止并交人工 |
| 持续运行 | 至少一次连续 24 小时受控运行，包含定时事件、进程重启和停滞注入；使用持久 Fake/Stub、成本封顶、终止开关，记录资源曲线与异常；加速时钟测试另列，不能代替真实墙钟观察 |
| 评测与交付 | 确定性控制断言全部通过；固定场景的任务完成质量、时延、总成本、人工介入和通知量可复算；独立设计、排错、迁移考试通过 |

环境相关的性能阈值在第 33 周先约定并记录，随后冻结。建议本地 Fake 条件下控制命令持久接收 P95 ≤ 2 秒、队列长度 ≤ 100、单任务重试 ≤ 2 次；这是练习起点，不能套用为真实服务承诺。第 40 周至少重复三轮相同任务、到达顺序和硬件条件，分别报告每轮结果与样本量；真实模型质量/费用、持久 Stub 正确性和加速时钟时间不能混报。

对照方案为原单会话串行执行与新增调度方案，固定模型快照、数据、工具权限、总预算、评分规则和外部条件，只改变调度架构。质量不能以未经批准的副作用换取，安全断言不得让位于性能。没有收益也可以凭完整实验和独立能力通过课程，但应作出维持单会话、调整或 No-Go 决策，不得宣称系统已经适合推广。

## 独立考试与学习证据

- 第 36 周只给任务目标、资源边界和成功条件，不指定调度实现；学习者独立画边界、选择方案并完成最小变体。
- 第 40 周复用平台底座，讲师临场更换渠道、权限条件或故障位置；学习者独立设计一个约束变体、实现关键路径、诊断一个陌生故障，并解释取舍。
- 练习可以按 H1→H4 提示阶梯辅助；考试不得使用事先给出的完整实现。用过完整答案的练习不能直接充当独立考试证据。
- 每日/每周给出“通过、部分通过、未通过”，阶段出口仅“通过/未通过”；掌握度、学习债务和复习安排仍遵守[讲师规范](07-instructor-supervision.md)。

- [Domain model](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/001-domain.md)与[Architecture](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/007-architecture.md)：用于理解事件、任务与执行的分工；课程保留现有 Task/Run 模型，不逐一复制上游领域命名。
- [Authorization](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/002-authorization.md)：用于讨论主动触发与授权的区别。课程采用更严格的执行路径校验，暂停后恢复、派发及每次副作用前重新核对有效权限。
