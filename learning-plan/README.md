# 32 周主线与 Super-agent 强化路线

## 计划定位

本计划面向具备基础开发能力、但没有 AI、机器学习、LLM、RAG 和 Agent 知识的开发者，围绕 **AI 应用与 Agent 工程、AI 平台与治理、垂直业务落地** 三个方向推进。每天投入约 1 小时，32 周总计约 224 小时，最终交付 `AI Agent Platform + Business Case`。

224 小时的计划范围是一个可运行、可演示、具备基础生产约束的平台 MVP 和一个真实或高保真业务试点闭环。语言桥接、补救、外部系统协调可能延长实际周期；周次表示学习顺序，不能按日历自动推进。完成后仍需要通过真实流量、多个业务场景和持续运维提升熟练度。

阶段文档给出 32 周排期和四列表格；[逐节课程教程](tutorials/README.md)进一步把 224 节课逐节展开为“为什么学、这个是什么、怎么学、怎么验证学会了”，并提供独立尝试后使用的参考答案。课程仓库的 `deliverables/week-XX/README.md` 只定义公共要求；个人进度和通过状态以个人学习仓库的同路径文件为准。

| 项目 | 安排 |

## 开发语言路线

课程不是让学习者在第一天同时学习 Java、Python 和 TypeScript，而是按职责分阶段切换：

```text
第 1–4 周：Python 建立 AI 原理和原生协议直觉
→ 第 5–8 周：Java/Spring AI 建业务与平台基础
→ 第 9–13 周：Python 学 Agent 运行时
→ 第 14–32 周：Java 控制面 + Python 执行面，按需增加 TypeScript 控制台
```

Java 21 是最终平台的主工程语言，Python 3.11+ 是 AI 实验与 Agent 执行语言，TypeScript/React 只承担最小控制台。每次语言切换使用 15–30 分钟桥接任务，并通过运行、测试和失败案例验收；不要求先完成整门语言教程。完整周次、职责边界和替代规则见[开发语言路线与切换策略](01-language-roadmap.md)。

## 学习者起点

默认已经具备：

- 至少一种主流编程语言的开发和单元测试能力。
- Git、命令行、IDE、HTTP、JSON、数据库和环境变量基础。
- 阅读错误日志、缩小问题范围和按 README 运行项目的经验。

不要求预先具备：

- AI、机器学习、深度学习、概率统计或线性代数知识。
- Token、Embedding、Prompt、RAG、Tool Calling、Agent 或 Eval 心智模型。
- Spring AI、LangChain、LangGraph、Claude Agent SDK 或 MCP 使用经验。
- Java 21、Spring Boot 或 Python 异步编程的完整熟练度。

课程对 Java、Spring Boot 和 Python 采用“完成当周任务所需的最小桥接”，不会把通用语言教程塞入 AI 主线。如果 Git、HTTP、测试或基础编程也不熟练，需要在课程外补齐，并相应增加实际投入时间。

每个主题按四级掌握，阶段出口至少达到 L3，最终核心模块达到 L4。

| 方向 | 重点周次与课时 | 要解决的问题 | 这段学习结束时的交付 |
| --- | --- | --- | --- |
| AI 应用与 Agent 工程 | 第 1–16 周，约 112 小时 | 如何让模型利用资料和工具完成任务，并解释成功与失败？ | 可运行、可测试、可评测的知识与研发助手 |

这是学习重心的划分。评测、权限和失败处理从前期就开始练，后期再统一为平台能力；业务问题在前期作为练习背景和待验证假设，第 25 周起完成正式调研与选择。最后同时验收平台与业务，任何一项都不能替代另一项。

必修技术顺序保持为：

```text
LLM 原理与原生 API
→ Java / Spring AI / RAG / Tool Calling
→ LangChain
→ LangGraph
→ Claude Agent SDK
→ Java 控制面 + Python 执行面
→ 工作流、治理、Eval 与运维
→ 业务调研、流程优化、接入与试点
```

Spring AI、LangChain、LangGraph 和 Claude Agent SDK 各自保留独立可运行成果，再在应用和平台中集成。前一阶段留下的输入、失败案例和测试继续复用；框架对比固定任务、数据、模型条件和评分口径。

## 贯穿课程的项目

优先复用一组练习资料、工具和失败案例，让项目逐步演进。建议沿用第 16 周的“知识与研发助手”，并把“研发问题或内部 IT 工单处理”作为后续业务候选：检索知识、查询问题状态、给出有依据的建议，必要时进入审批，再由隔离的执行任务处理构造项目。

这里是练习背景示例。第 25 周仍要比较候选场景、核实 Owner 和数据权限；现有代码不能代替需求证据。若客服售后或运营分析更适合实际业务，可复用平台后切换场景，保留框架独立成果和原评测基线。

| 进展 | 在现有成果上增加什么 | 可检查的结果 |
| --- | --- | --- |
| 第 1–4 周：原生实验 | 用自建小样本理解调用、工具请求和失败；先保留输入与预期 | 能解释一条请求，手写关键路径并定位错误 |
| 第 5–13 周：独立能力 | 分别实现检索、工具、状态工作流和隔离执行；比较相同任务 | 每个框架有独立运行入口、测试和边界说明 |
| 第 14–16 周：完整应用 | 用版本化协议连接能力，建立固定评测和运行追踪 | 从请求到结果可追踪；拒答、审批和执行失败可复现 |
| 第 17–24 周：平台化 | 从应用提取资源、版本、运行和策略管理，复用已有执行模块 | 同一任务绑定发布快照，可审计、停止、恢复和回滚 |
| 第 25–32 周：业务验证 | 按调研选定流程，完成接入、用户验收、试点与复盘 | 同口径比较改造前后效果，说明成本、失败和适用边界 |

自建或脱敏数据、代码和业务材料写入个人仓库。前期练习集与第 15 周固定的开发/留出集应区分；冻结后的留出集不用于逐题调参，后续业务反馈以数据集新版本进入回归。

## 平台参考架构

```text
业务系统 / 管理控制台 / Open API
                 ↓
Java Control Plane
├── Tenant / Project / RBAC
├── Agent Registry / Version / Release
├── Model Gateway / Policy / Quota
├── Tool & MCP Registry / Credential Reference
├── Knowledge Base / Index Version
├── Workflow Definition / Run Management
└── Audit / Eval / Observability API
                 ↓
Python Agent Runtime
├── LangChain：模型、工具与结构化 Agent
├── LangGraph：状态、路由、Checkpoint 与 HITL
└── Claude Agent SDK：隔离的开放式执行任务
                 ↓
PostgreSQL / Vector Store / Object Storage / Sandbox
```

控制面负责配置、权限、版本和审计；执行面只接收经过授权且已发布的不可变快照。业务权限必须由平台代码执行，不能交给 Prompt 或模型判断。

## 业务场景选择标准

第 25 周必须选择一个真实或高保真案例。合格场景应同时满足：

- 有明确业务负责人、用户和可量化目标。
- 现状至少包含三个步骤或两个系统之间的协作。
- AI 能解决非确定性任务，但关键规则仍可由代码约束。
- 数据来源、权限和人工兜底可以说清楚。
- 四周内能够做小范围试点，不依赖大规模组织改造。

不选择“做一个万能聊天机器人”作为场景。优先考虑知识密集、重复判断、跨系统协作、结果可复核的流程。

- 第 4 周：能解释并手写模型调用、流式处理和 Tool Loop。
- 第 8 周：能用 Java 构建安全的 RAG 与 Agent 基础能力。
- 第 13 周：能构建持久化工作流和隔离的执行型 Agent。
- 第 16 周：有一个可评测、可观测的端到端 AI 应用。
- 第 20 周：完成平台核心控制面和资源版本管理。
- 第 24 周：平台工作流、运行治理和发布门禁可用。
- 第 28 周：完成一个业务场景的调研、流程优化和接入设计。
- 第 32 周：完成业务试点、生产硬化、效果复盘和平台交付。
- 第 36 周（强化）：三任务与两入口协作通过独立设计、实现与边界变体验收。
- 第 40 周（强化）：纠正、恢复、持续运行、固定对照及独立交付考试通过。

里程碑依据实际成果评审。每个阶段仍需独立实现、故障诊断、Teach-back 和未练习过的变体，不能用集成 Demo 替代框架独立验收。具体标准见[成果与提交标准](06-deliverable-standards.md)和[讲师监督规范](07-instructor-supervision.md)。

## 执行节奏与调整

每天先确认个人仓库当周状态和遗留问题，再从[当周教程](tutorials/README.md)选择一个约 1 小时的核心目标，最多引入一个核心新概念。每天留下一个实践成果、一个失败或边界观察，并用自己的话复述；时间分配与周节奏见[学习方法](00-learning-method.md)。

周末用个人仓库的 `deliverables/week-XX/README.md` 汇总证据并评审。周核心成果未通过时，先补依赖能力；同一知识点连续两次未通过时安排补救，记录原因、补救验收和后续影响。阶段前测不通过时先做 15–30 分钟桥接，实际日历可以后移，阶段出口保持不变。

每周阅读行业动态时只记录“解决哪个当前问题、落在哪一周、用哪个已有样例验证”。选做内容在必修验收完成后安排，额外投入单独记录；不挤占原理、失败、安全和复盘时间。

## 资料使用原则

每个每日课程的“当天学习建议”末尾都附有“相关资料”链接。每天约 20 分钟的资料学习只阅读与当天任务直接相关的章节，并把版本、关键结论和仍待验证的问题记入周笔记；链接是实践入口，不替代亲自运行、失败实验和 Teach-back。

框架和 API 优先链接当前官方入口，学习前必须核对页面主版本与工程兼容关系。2026-09-06 Spring AI 默认页已为 2.x（面向 Boot 4.x），本课程仍使用 Boot 3.x，须选择兼容的官方 BOM 与版本文档；差异记录见[版本核验](10-job-market-alignment.md#版本核验与维护)。协议固定到明确的稳定版本，避免课程内容随网页默认版本静默变化。平台工作流设计应利用持久化、人工审批和故障恢复能力；LangGraph 的 Checkpoint 用于 HITL、恢复和调试，Spring AI 的模型、工具与向量调用可以接入统一观测，MCP HTTP 接入必须按协议实现授权和资源绑定。MCP 课程当前以 `2025-11-25` 稳定版为基线，`2026-07-28` Release Candidate 暂不作为实现验收依据。

相关官方资料：[LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)、[Spring AI Observability](https://docs.spring.io/spring-ai/reference/observability/index.html)、[MCP Authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)、[Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview)。

每天先从[逐节课程教程](tutorials/README.md)进入当周课程，通用执行方式见[学习方法与建议](00-learning-method.md)，当周语言和切换桥接见[开发语言路线](01-language-roadmap.md)，讲师监督和掌握度判定见[讲师监督与掌握度评估](07-instructor-supervision.md)，每周提交前检查[成果与提交标准](06-deliverable-standards.md)。本次学习者起点调整的边界和迁移依据见[AI 零基础开发者课程改造设计](08-ai-zero-foundation-curriculum-design.md)。
