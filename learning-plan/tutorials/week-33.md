# 第 33 周教程：独立设计与单会话基线

> 计划来源：[10-super-agent-coordination.md](../stages/10-super-agent-coordination.md)。阶段文档决定课程任务和验收，[第 33 周公共成果要求](../../deliverables/week-33/README.md)定义门禁；学习状态只记录在个人学习仓库。

## 本周先理解

### 为什么学

把持续协作需求转为可验证的任务边界，先建立公平对照。

### 这是什么

持续协作系统接收事件、管理长期目标并派发执行尝试；Task 是目标，Run 是一次尝试，模型建议由平台校验后才生效。

### 本周语言定位

复用原平台：Java 管任务、授权和持久状态，Python Worker 执行已授权快照，PostgreSQL 保存控制记录；先用持久 Fake/Stub 验证，真实模型与外部系统验证范围单列。完整职责、切换桥接和替代规则见[开发语言路线](../01-language-roadmap.md)。

### 本周学习策略

- 每天只完成下面一节，控制在约 1 小时，不提前堆叠下一节的新概念。
- 先预测再实验；先保存原始证据，再写结论；失败样例与正常结果同等重要。
- 首次遇到术语时补齐：一句话定义、输入输出、开发类比、类比边界、反例和“不是什么”。
- 使用 H1→H4 提示阶梯；若使用完整参考答案，必须额外完成一个不同输入或约束的变体。

### 周一 · 第 1 节：前测与任务需求契约

**为什么学**

本节只推进“前测与任务需求契约”，为“前测结果、一个可验收需求和一个明确拒绝的越界需求”留下可以复核的证据。

**这是什么与今天的边界**

完成阶段前测；用现有 Scene Brief 方法写角色、三类研发任务、允许副作用、成功条件和人工接管点。需求契约把模糊目标变成可验证输入输出，类比接口验收；“自动解决所有问题”不是契约。首次接触术语时，用自己的话补齐定义、输入输出、开发类比及其局限、反例和“不是什么”；复习日不再增加新概念。

**原理问题**

怎样把‘持续修复问题’拆成可验收且有停止条件的授权范围？

**怎么学（约 60 分钟）**

1. `0–5 分钟`：检查上次遗留问题和本节依赖，先写正常结果与失败结果的预测。
2. `5–15 分钟`：仅阅读当前任务相关段落，对照既有实现；记录来源版本和差异。考试日这段时间用于独立分析约束。

4. `40–50 分钟`：验证反例：需求要求 Agent 自动合并所有修改，是否超出当前交付范围？
