# 第 34 周公共成果要求：多任务调度与隔离

本目录接收课程计划与统一门禁，输出可供个人仓库引用的验收清单。只保存公共要求；禁止填写个人状态、评分、运行日志、真实凭证或唯一成果副本。

计划来源：[阶段计划](../../learning-plan/stages/10-super-agent-coordination.md)；学习步骤：[本周教程](../../learning-plan/tutorials/week-34.md)。本周属于原 32 周毕业后的强化范围。

## 必交证据

- 有界队列与容量策略，三个任务同时活动且慢任务不阻塞另外两个。
- 公开公平规则、租约 owner/epoch/期限；两个 Worker 竞争执行权有断言。
- 每任务独立沙箱目录与工具范围，跨目录/Project 被拒绝。
- 全局和单任务预算并发预留、结算和取消释放；资源上限可观察。
- 三任务 Trace、资源耗尽失败与排错记录；崩溃接管未验证部分交第 38 周。

## 独立掌握验证

容量从三改二并改变到达顺序，独立预测并验证；解释租约为何不足以避免重复副作用。

## 个人记录要求

在个人仓库的 `deliverables/week-34/README.md` 链接真实成果，填写实际命令、版本、输入输出、退出状态、失败定位、关键取舍和未验证范围。设计写 `docs/`，实现写对应语言目录，数据写 `data/`，隔离任务写 `sandbox-workspaces/`，不把唯一成果复制进课程仓库。

讲师按[统一规范](../../learning-plan/07-instructor-supervision.md)给出“通过、部分通过、未通过”，记录掌握度、Teach-back、变体、学习债务和下次复习；只运行示例最高为 L1。公共模板的存在不代表学习通过。

## 验收与后续输入

本周证据须满足[专项门禁](../../learning-plan/11-super-agent-reinforcement.md#固定评测集与专项门禁)和[成果标准](../../learning-plan/06-deliverable-standards.md#super-agent-强化成果索引)。未通过先补救，列出下一步可依赖的接口、数据、版本和待验证项；未运行的实验不能填入已通过结果。
